# 如何导入自己的指南

本仓库**不附带**任何指南或共识的全文，也不附带大段摘录。版权内容须由使用者自行准备，并确保自己有权在本地使用。

分析时只应使用已经导入、并且已经读过相应范围的来源。未读全文的文献，不得当作已经掌握，也不得根据标题、摘要或目录去写具体的饮食、运动或用药建议。

## 建议的本地布局

在 `knowledge-base/` 下，你可以自行增加一个不会被 Git 提交的目录来存放原文，例如：

```
knowledge-base/
  README.md                 # 本仓库已提供的说明
  sources.example.md        # 索引模板（可复制后改名使用）
  sources.example.json      # 供程序读取的示例索引
  sources.md                # 你的实际索引（不要提交指南正文）
  sources.json              # 你的实际机器可读索引（可选）
  sources/                  # 你保存的全文或选读复印件（已被 .gitignore 忽略）
```

不要把指南 PDF、OCR 全文或长摘录提交到本项目的公开仓库。

## 每条来源至少应记录的信息

无论使用 Markdown 还是 JSON 索引，每条来源建议包含：

| 字段 | 说明 |
| --- | --- |
| `id` | 本地短标识，供建议条目引用，例如 `local-consensus-2024` |
| `title` | 文献或共识的正式名称 |
| `version` | 版本，若有 |
| `year` | 发表或更新日期 |
| `publisher_or_society` | 发布机构，若已知 |
| `scope` | 你实际读过并允许程序使用的范围：全文，或明确列出的章节 |
| `read_status` | 必须如实填写。`full_text_read` 表示你已读全文；`selected_sections_read` 表示只读了 `scope` 里列出的部分；`unread` 表示尚未阅读 |
| `path` | 原文在你本机的路径（不要把该文件提交到 Git） |
| `applies_to` | 适用人群或场景的简要说明，须来自该文献自身，而不是推断 |
| `notes` | 使用限制，例如“仅用于门诊 2 型糖尿病，不用于妊娠” |

`sources.example.md` 和 `sources.example.json` 给出的是虚构的索引行，用于演示字段，并不代表任何真实指南的内容。

## 未读全文不得当作已掌握

流水线和人工分析都应遵守：

- `read_status` 为 `unread` 的来源，不得用于生成饮食、运动、监测建议，也不得用来确定目标值。
- 只读了部分章节时，建议和目标只能引用这些章节；不得根据书名或相邻章节标题延伸。
- 索引里没有的来源，不得在文稿中写成“依据某某指南”。
- 不得把模型或个人的医学通识，标记成某条知识库来源。

代码中的对应逻辑见 `src/cgm_report_advisor/knowledge.py`。第一版只读取索引并检查阅读状态，不会自动“理解”指南全文。把原文中的哪一条改写成可引用的建议条目，需要使用者自行整理，或在后续版本中再设计受约束的导入方式。

## 与资料收集、目标值的关系

知识库决定了两件关键的事：

1. **分析某类患者或给出某类建议时还缺哪些资料。** 不同来源、不同患者类型需要的项目可能不同，因此不要在程序里写死一份对所有人通用的问卷。
2. **指标目标和具体处方从哪里来。** 数据质量是否足够、目标范围内时间的目标值、低血糖分层、饮食份量和运动注意事项，都必须指向已读来源，并写明适用人群。来源之间不一致时，并列引用，不要折中。

## 更新知识库时

更换版本或增加来源后，应同步更新索引中的版本、年份和阅读状态。旧建议条目如果引用的是已经撤换的版本，不应在未核对的情况下继续输出。
