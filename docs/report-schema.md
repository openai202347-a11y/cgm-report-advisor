# 报告提取字段

本文件描述从 CGM 图形报告中整理出的指标字段。它是记录格式，不是“应当达到的治疗目标”。目标值只能来自已导入的知识库，并写明适用人群。

## 总原则

- 只提取报告原文已经写出的内容。没写的字段保持为空，不要用计算、经验或另一份报告填补。
- **单位、小数位、指标名称保留原文。** 报告用 mmol/L 就记 mmol/L，用 mg/dL 就记 mg/dL；不要在提取阶段擅自换算后覆盖原文。若后续分析需要换算，应另存换算结果，并同时保留原文。
- 估算糖化血红蛋白（eHbA1c）与葡萄糖管理指标（GMI）不要混称。报告写哪一个就记哪一个。
- 目标范围内时间、高于目标时间、低于目标时间的分层切点（例如 3.9–10.0 mmol/L）必须按报告印刷的区间记录，不要改成知识库中的另一套切点后再提取。解读时如果知识库使用另一套分层，应并列说明，而不是改写提取结果。
- 身份类信息（姓名、电话、掩码电话、证件号、住址等）不应写入对外文稿，也不应成为本模式中需要导出的字段。实现提取器时可以在内部标记“报告含有身份信息，已忽略”，但不要把这类原文保存进将要发布的结构化结果。

## 建议字段

下列字段名供结构化文件和代码数据类使用。JSON 示例见 `examples/fictional-report-metrics.json`。

### 监测与质量

| 字段 | 含义 | 记录方式 |
| --- | --- | --- |
| `wear_start`, `wear_end` | 佩戴或报告起止日期（及时间，若有） | 按原文 |
| `wear_days_stated` | 报告写明的佩戴天数或有效天数 | 按原文；未写则留空，不要用起止日期自行推算后当作报告原值 |
| `coverage` | 数据覆盖率、有效数据比例或完整天数说明 | 保留原文数字和单位（如 `%` 或“完整 24 小时的天数”） |
| `data_quality_note` | 报告对缺失、中断、传感器异常的说明 | 原文摘述，避免大段抄录无关页眉页脚 |
| `reference_only` | 报告是否声明仅供测试或参考、不能作为调整治疗的依据 | 布尔值，并另存 `disclaimer_text` 的简短原文 |

### 总体葡萄糖指标

| 字段 | 含义 | 记录方式 |
| --- | --- | --- |
| `mean_glucose` | 平均葡萄糖（有的报告写作 MG） | 数值 + 原文单位 |
| `sd` | 标准差（SD） | 数值 + 原文单位 |
| `cv` | 变异系数（CV） | 数值 + 原文单位（通常为 `%`） |
| `e_hba1c_or_gmi` | 估算糖化血红蛋白或 GMI | 在子字段中标明报告使用的名称；数值 + 原文单位 |
| `glucose_min`, `glucose_max` | 报告给出的最低、最高葡萄糖 | 数值 + 单位；若同时给出发生日期或时段，另记，不要推断 |
| `very_low_stated` | 报告是否写明低于某一更低切点（例如低于 3.0）的数值或次数 | 只记报告写出的内容；报告没印出的，不要记成 0，也不要记成“未发生” |

每个指标建议使用同一结构：`value`、`unit`、`label_in_report`，必要时加 `as_printed`（报告上的完整字符串）。

### 时间占比分层（TIR / TAR / TBR）

用列表记录每一层，而不是写死某一套切点：

| 字段 | 含义 |
| --- | --- |
| `bands[].label` | 报告中的名称，如目标范围内时间、TIR、TAR、TBR，或颜色分区名称 |
| `bands[].range_low`, `bands[].range_high` | 该层的葡萄糖区间，按原文 |
| `bands[].unit` | 该层单位 |
| `bands[].percent` | 时间占比，按原文 |
| `bands[].duration` | 若报告另外给出了小时、分钟或事件次数，按原文记录 |

不要把软件仪表盘上单独的“风险等级”自动写入这些分层。若报告另有低血糖风险仪表或类似读数，应放在 `software_gauges` 中单独保存，并在解读时按流程文档处理：知识库未支持、或与 TBR 明显不符时，不得直接说成风险高。

### 分时与事件

| 字段 | 含义 |
| --- | --- |
| `time_of_day_patterns` | 报告对凌晨、早餐前、午餐后、晚间等时段的文字或图表说明 | 用简要条目记录“原文怎么说”，不要改写成因果解释 |
| `hypoglycemia_events` | 报告列出的低血糖事件或低于某切点的片段 | 时间、数值、持续时间仅在原文有时填写 |
| `hyperglycemia_events` | 报告列出的明显偏高片段 | 同上 |

### 佩戴者核对（仅供内部区分，不用于对外展示）

| 字段 | 含义 |
| --- | --- |
| `wearer_key` | 使用者指定的匿名区分号，如 `fictional-wearer-A` | 不要使用真实姓名或病历号 |
| `same_wearer_confirmed` | 多份报告是否已经由使用者确认属于同一人 | 未确认则为空或 `false`，流水线不得自行当作同一人 |

## 不要放入提取结果的内容

- 真实姓名、电话（含掩码）、住址、证件号、病历号等身份信息。
- 对缺失指标的估算值。
- 知识库中的目标值（那是解读依据，不是报告提取结果）。
- 为了让表格好看而补上的“默认单位”或“典型切点”。

## 与代码的对应

`src/cgm_report_advisor/models.py` 中的 `ExtractedReport` 按上述字段建模。`extract_report.py` 提供提取接口，以及从结构化 JSON 载入的实现；PDF 全文解析需要另写厂商提取器，且同样遵守“原文没有就不填”。
