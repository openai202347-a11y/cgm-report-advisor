# 建议可追溯性与配图规则

给患者的饮食、运动和监测建议必须能对上知识库里已经收录的指南或共识。配图只是把知识库已经写明的份量或动作画出来，不是另写一套建议。

## 可追溯性

每一条具体建议都应带有来源信息，至少包括：

- 文献或共识的名称；
- 版本或年份；
- 可供核对的位置（章节、条目、表格编号等）。

不要在对外文稿中大段摘录受版权保护的指南原文。写清出处，让使用者能够在自己保存的知识库中核对即可。

### 允许写什么

- 知识库对该类患者已经写明的饮食原则、份量、食物举例、运动类型、时长、强度或注意事项。
- 知识库已经写明的监测建议，例如何时查看血糖、低血糖后如何按共识处理（仍须注明来源）。
- 把报告中的时段特点与知识库条目对应起来的说明，前提是没有把未记录的某顿饭或某次运动说成原因。

### 不允许写什么

- 知识库没有写明的用法、剂量、服药时点、食物清单、具体份量或运动处方。不要用“一般认为”“通常可以”等通识补上。
- 未在知识库中出现的数量，例如自行把“适量水果”改成“每天半个苹果”，或把“规律活动”改成“每天快步走 30 分钟”。
- 建议患者自行增减处方药物剂量。涉及调药，一律写咨询医生。
- 把软件里单独的低血糖风险仪表，在知识库未支持或与低于目标时间明显不符时，写成“低血糖风险高”。
- 在用餐内容未知时，把某一时段偏高归因于某一种具体食物。

同一问题如果知识库中有不同框架（例如不同共识对目标范围内时间的目标值或适用人群写法不同），应在文稿中并列写出各自的来源和适用条件，不要合并成一条知识库中并不存在的新标准。

## 配图规则

为患者配图的目的是降低理解成本：如果知识库写的是“每天半个水果”，就画半个该水果，而不是一整盘；如果写的是某一种动作，就画该动作。

### 何时可以配图

同时满足以下条件时，才为该条建议配图：

1. 建议本身是具体的饮食或运动条目，而不是笼统原则；
2. 份量或动作已经在知识库中写明，并且这条建议的文字没有超出该范围；
3. 图只图解上述已经写明的份量或动作。

### 何时不得配图，或必须拒绝生成

- 知识库只说“增加蔬菜”或“保持活动”，没有给出可画出来的份量或动作。
- 为了让页面更好看而增加知识库中没有的食物、份量、餐具或动作。
- 制作“好水果 / 坏水果”“可以吃 / 不能吃”一类分类图。这类图往往会加入知识库并未列出的判断。
- 图中出现药盒、药片上的商标，或可辨认的患者面部、姓名、病历号等身份信息。
- 把未提供的药物剂量画成药板或注射器刻度。

### 画师或生成提示应遵守的约束

向配图模块提交的说明里，只能包含知识库已经出现的食物名称、份量词和动作描述。不要在提示中追加“再摆两颗草莓让构图更丰满”之类的内容。若无法在不添加额外元素的前提下做图，就宁可没有图。

代码里的对应检查见 `src/cgm_report_advisor/illustrate.py`：没有来自知识库的份量或动作原文时，不得生成配图请求。

## 建议条目的建议结构

便于机器检查和人工核对的一条建议，至少包含：

- 类别：饮食、运动、监测，或“请咨询医生”；
- 给患者看的句子；
- 来源名称、版本或年份、位置；
- 可选：知识库中的份量或动作原文（有则允许配图，无则不准配图）；
- 可选：配图文件路径或占位说明。

虚构示例见 `examples/fictional-intake.md` 和流水线在资料齐全时的演示输出，其中的食物和份量都明确来自示例知识库条目，而不是报告里的想象。
