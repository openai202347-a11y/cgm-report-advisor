# 路线图

## 第一版范围

第一版把已经在人工分析中使用的流程写成可公开的目录、说明和轻量代码骨架，方便在本地复用，而不是做成医院信息系统。

第一版包括：

- 标准流程和解读顺序的文档；
- 报告提取字段、资料收集原则、建议可追溯性与配图规则、知识库导入方式的说明；
- 不包含指南全文的知识库占位目录和索引模板；
- 明确标注为虚构的示例资料和示例指标；
- Python 流水线骨架：提取接口、资料缺口检查、在资料不全时拒绝输出饮食运动处方、配图前检查份量或动作是否来自知识库、渲染带声明的文稿；
- 少量针对上述规则的测试。

第一版不包括：

- 各厂商 CGM PDF 的完整自动解析；
- 内置的指南或共识正文；
- 自动根据曲线开出知识库中没有写明的食谱或运动计划；
- 登录系统、多用户报告库、患者端应用；
- 任何医疗器械认证或“可替代医生”的能力。

## 明确列为后续、且涉及健康数据合规的事项

下列方向如果要做，都超出第一版，并且会涉及健康数据或个人信息的收集、存储、传输和访问控制。启动前需要单独考虑适用的法律法规、机构制度和安全设计，不能把当前这种本地流程骨架直接上网。

- **登录与权限。** 多使用者使用时的身份鉴别、授权和审计。
- **多端报告库。** 在服务器或云端保存报告、用药史和历史建议，供医护在不同设备上调取。
- **医院信息系统对接。** 与电子病历、医嘱或检验系统交换数据。
- **微信小程序或其他公众网络上的患者端。** 向患者收集报告或推送建议。

这些后续事项在未完成合规评估和相应实现之前，不应作为本项目已经具备的功能来介绍。

## 可以考虑、但仍属后续的技术工作

在仍然保持“本地、可开源、不内置指南全文”的前提下，后续可以考虑：

- 针对单一厂商报告格式的可选提取插件，并继续禁止填补原文没有的值；
- 把使用者已经整理好的知识库条目（短句、出处、适用人群、份量原文）做成受约束的引用表；
- 更完整的多报告同一佩戴者核对辅助（仍须人工确认，不得自动混套用药和病史）；
- 配图占位到本地示意图库的映射，示意图本身也不得加入商标或身份信息。

以上都不是第一版的交付承诺。
