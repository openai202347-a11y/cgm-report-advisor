# 路线图

## 第一版范围

第一版把已经在人工分析中使用的流程写成可公开的目录、说明和轻量代码骨架，方便在本地复用，而不是做成医院信息系统。

第一版包括：

- 标准流程和解读顺序的文档；
- 报告提取字段、资料收集原则、建议可追溯性与配图规则、知识库导入方式的说明；
- 不包含指南全文的知识库占位目录和索引模板；
- 明确标注为虚构的示例资料和示例指标；
- Python 流水线骨架：提取接口、资料缺口检查、在资料不全时拒绝输出饮食运动处方、配图前检查份量或动作是否来自知识库、渲染带声明的文稿；
- 少量针对上述规则的测试。

第一版不包括：

- 各厂商 CGM PDF 的完整自动解析；
- 内置的指南或共识正文；
- 自动根据曲线开出知识库中没有写明的食谱或运动计划；
- 登录系统、多用户报告库、患者端应用；
- 任何医疗器械认证或“可替代医生”的能力。

## 明确列为后续、且涉及健康数据合规的事项

下列方向如果要做，都超出第一版，并且会涉及健康数据或个人信息的收集、存储、传输和访问控制。启动前需要单独考虑适用的法律法规、机构制度和安全设计，不能把当前这种本地流程骨架直接上网。

- **登录与权限。** 多使用者使用时的身份鉴别、授权和审计。
- **多端报告库。** 在服务器或云端保存报告、用药史和历史建议，供医护在不同设备上调取。
- **医院信息系统对接。** 与电子病历、医嘱或检验系统交换数据。
- **微信小程序或其他公众网络上的患者端。** 向患者收集报告或推送建议。

这些后续事项在未完成合规评估和相应实现之前，不应作为本项目已经具备的功能来介绍。

## 可以考虑、但仍属后续的技术工作

在仍然保持“本地、可开源、不内置指南全文”的前提下，后续可以考虑：

- 针对单一厂商报告格式的可选提取插件，并继续禁止填补原文没有的值；
- 把使用者已经整理好的知识库条目（短句、出处、适用人群、份量原文）做成受约束的引用表；
- 更完整的多报告同一佩戴者核对辅助（仍须人工确认，不得自动混套用药和病史）；
- 配图占位到本地示意图库的映射，示意图本身也不得加入商标或身份信息。

以上都不是第一版的交付承诺。其中“受约束的引用”和“发现指南有没有更新”的第一块骨架，见下一节；它不改变第一版流水线的行为。

## 下一步：文献监测与受约束的本地导入

这一步要解决两件事：怎样在本地把使用者有权使用的指南文本变成**待审草稿**，以及怎样知道某个系列可能有了新版本。它仍然不把指南全文放进公开仓库，也不代替人阅读。

### 受约束的本地导入

自动“理解”指南 PDF，在这里只指一次受约束的本地导入：

- 使用者把自己有权使用的文件放进被 Git 忽略的 `knowledge-base/sources/`。
- 程序抽出文本，按章节切开，并为能定位的片段写下短草稿。草稿尽量带上这些字段：`kind`、`applies_to`、逐字的 `portion_or_action`、定位（页码或标题）、`source_quote`。
- 只有原文自己写出了明确的数量、时长、频率或动作，才填写 `portion_or_action`。程序不编造份量，也不用医学通识把缺口补上。没有写明份量的句子，不得到一个编出来的份量。
- 表格和成串的数字很容易抽错，因此不从表格自动生成份量，留给人工核对。
- 草稿的 `review_status` 一开始是 `pending_review`。来源在被接受之前仍是未读。
- 使用者确认自己读过的范围并接受条目之后，来源才变成 `full_text_read` 或 `selected_sections_read`，条目才可以进入饮食、运动或监测建议。
- 不同来源互相冲突时，并列保留，不折中成一条新的标准。
- 导入草稿和抽出的文本放在被 Git 忽略的 `knowledge-base/drafts/` 与 `knowledge-base/extracted/`。

对应代码是 `src/cgm_report_advisor/ingest.py`。第一版的 `python -m cgm_report_advisor --metrics ...` 不读取这些草稿。

### 监测并提醒，而不是自动下载

跟踪新指南是“发现并提醒”，不是把全文自动下载进公开仓库。

- 公开的书目清单记录系列名称、学会或出版社、官方页面或 DOI（只写已经核对过的），以及清单编写时从该页面或书目记录看到的年份或版本。
- 核对可以使用 PubMed、Crossref、Europe PMC 或官方页面，但只要书目信息：题名、年份、标识和获取位置。
- 若可能有更新的版本，报告写明是哪一系列、看到的年份或版本，以及到哪里按官方途径获取。在线核对失败就跳过该条并说明原因，不编造“已经更新”。
- 使用者自己合法取得文件，放进 `knowledge-base/sources/`，运行导入，再人工审阅。
- 同一系列接受了更新的版本之后，旧版本要标成已撤换，其条目不能被悄悄继续使用。
- 不抓取、也不提交受版权保护的 PDF。

对应代码是 `src/cgm_report_advisor/watch.py`。清单见 `knowledge-base/watchlist.json`。
